# 7. 이번 작업: 제목 3개

입력 제품·채널·게시물 종류에 맞는 **제목(첫 줄 훅) 3개**를 만든다. 본문은 아직 만들지 않는다.

- 제목은 그 채널의 첫 줄이 된다: **상세페이지는 큐텐 상품명(타이틀)**, 인스타는 캡션 첫 줄·커버, X는 첫 줄, 배너는 메인 카피.
- **상세페이지(큐텐) 상품명**은 3장 01의 「상품명」 형식을 따른다: `【公式】リーフアンド(Leaf&) {product_ja} {kind_ja} {volume} / 효능・효능・효능`. 제품명·종류·용량 자리는 `{product_ja}` `{kind_ja}` `{volume}` 그대로 두고(코드가 채운다), 끝의 효능 3개는 검색어·소구점에서 효능 범위 안의 말만 고른다. 3개의 차이는 효능 묶음(소구점 / 사용감 / 고민·시즌·행사)으로 낸다.
- 게시물 종류가 `mega_sale` 이면 3개 모두 메가와리 게시물이다 (상세는 【メガ割】를 붙이고, SNS는 첫 줄에 「メガ割」를 넣는다). `[행사]` 가 「없음」이면 【メガ割】를 붙이지 않는다.
- **서로 다른 각도**로 3개를 만든다: ① 소구점 ② 사용 장면 ③ 시즌·행사(게시물 종류가 general이면 고민·검색어). 인스타·X에서 ③은 `요즘 뜨는 말` 이 있으면 그 고민·관심을 살린다 (공통 자가 점검 2번의 약기법 기준을 지킨다).
- 그중 **가장 추천 1개**를 고르고 이유를 쓴다. 나머지 2개에는 고를 때 참고할 점(장단점)을 쓴다.
- 길이: 상세페이지 상품명은 키워드 포함 한 줄(제품 정보가 앞에 오게), 인스타 20자 안팎, X 첫 줄 25자 이내, 배너 15자 안팎.
- 첫 줄 스타일(3장 02)은 각도에 맞게 고른다. 장식 기호는 쓰지 않는다.

**채널이 `qoo10_detail` 이면 3개 모두 반드시 상품명 형식이다** (문장형 훅 카피 금지). 예:
`【公式】リーフアンド(Leaf&) {product_ja} {kind_ja} {volume} / 保湿・うるおい・キメ`
끝의 3개는 **효능·사용감 낱말**만 쓴다. 성분명·「*」 각주·감각 의태어 나열(すーっと 등)은 넣지 않는다.

# 8. 출력 형식

JSON 하나만 출력한다. 설명 문장을 앞뒤에 붙이지 않는다.

```json
{
  "titles": [
    {
      "title_ja": "べたつかないのに、しっとり続く",
      "title_ko": "끈적이지 않는데, 촉촉함이 이어져요",
      "angle": "소구점",
      "recommended": true,
      "reason": "경쟁 제품 불만 1위 「끈적임」을 우리 칭찬 「산뜻한 흡수」로 뒤집었어요. 검색어 「化粧水」와도 이어져요."
    },
    {
      "title_ja": "洗顔後すぐ、すーっとなじむ",
      "title_ko": "세안 후 바로, 스르륵 스며들어요",
      "angle": "사용 장면",
      "recommended": false,
      "reason": "사용 장면이 분명하지만 소구점과의 연결이 1번보다 약해요."
    },
    {
      "title_ja": "乾燥が気になる季節に、毎日のうるおいを",
      "title_ko": "건조함이 신경 쓰이는 계절에, 매일의 보습을",
      "angle": "고민",
      "recommended": false,
      "reason": "계절 고민에 잘 맞지만 다른 제품과 차별점이 덜 보여요."
    }
  ]
}
```

- `titles` 는 정확히 3개. `recommended: true` 는 1개뿐이고 맨 앞에 둔다.
- `reason` 은 한국어 1~2문장. 어떤 소구점·키워드·강조할 방향을 왜 썼는지(또는 왜 반영하지 않았는지) 적는다.
